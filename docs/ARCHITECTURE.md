# Архитектура

Этот документ описывает PHP-версию на `main` и общие правила движения. В локальной ветке `no-server` опрос и хранение перенесены в браузер.

## Компоненты

- Интерфейс: Node.js 24, Vite, JavaScript ES-модули, Tailwind CSS 4, Leaflet 1.9.4.
- Локальный HTTP-сервер и отдельный сборщик: PHP 8.2+. Сборщик опрашивает API, сервер отдаёт снимок по `/api/state`. Браузер никогда не обращается к API расписания.
- `config/d2-stations.json` — каталог станций и исходное направление; `config/stations.json` — рабочие координаты и привязка к пути; `config/railway.geojson` — единая геометрия D2.
- `var/state.json` — атомарный снимок и история, `var/observations.json` — резервная копия истории. Папка `var/` не публикуется.
- Фронтенд: `src/map.js` собирает карту; `src/corridor.js` ограничивает область тайлов; `src/corridor-tiles.js` запрашивает и кэширует подложку; `src/trips.js` сопоставляет рейсы; `src/motion.js` вычисляет позиции; `src/train-renderer.js` рисует составы.

## Станции и направления

На D2 37 станций, 23 ID API. Станции без ID остаются на карте без вымышленного расписания. Геометрия содержит один репрезентативный путь на 1340 вершин и длиной 81,54 км; точные платформенные пути поездов не моделируются.

`travelDirection` постоянен на всём рейсе: `+1` — на юг, к Подольску; `−1` — на север, к Нахабино. Известная конечная имеет приоритет над флагами источника. Внешние конечные Серпухов и Львовская заданы как южные в `section.destinationDirections`. «Курский вокзал» — алиас Курской. Если конечная неизвестна, применяются сохранённое направление или флаг `toMoscow` с учётом стороны Курской. Рижская (ID 3987) передаёт одинаковый `toMoscow=false` для обоих направлений.

Подпись «В Москву»/«Из Москвы» меняется после остановки на Курской; физическое направление состава при этом не меняется. История с `directionNormalizationVersion` ниже текущей версии пересобирается сборщиком: направления исправляются, наблюдения одного поезда объединяются без изменения времени отправления.

## Опрос и идентификация рейсов

Работает один PHP-сборщик; блокировка `flock` не допускает второй экземпляр. Он опрашивает 23 станции последовательно: интервал между началами запросов не менее 1 секунды, пауза после цикла 300 секунд. Пауза и последний запрос сохраняются, поэтому быстрый перезапуск не обходит ограничения. Ошибка станции сохраняет её последние успешные данные. Публикация снимка атомарная; браузер обновляет его каждые 5 секунд независимо от числа вкладок.

Рейсы сопоставляются по номеру, устойчивому направлению и временному окну 3 часа. `scheduleTime` используется для идентификации и разделения повторных рейсов на одной станции, но движение привязано к `departureTime`. При наличии GPS или уникального ID источник не предоставляет; объединение — эвристика.

## Расчёт движения

`departureTime` — якорь станции. Состав стоит 15 секунд до и после указанного момента; секунды сохраняются. Не прибавлять `delaySeconds` повторно и не подменять якорь `scheduleTime`.

Между известными станциями движение распределяется по расстоянию и временам отправления. Для станции без API резервируется стоянка 30 секунд без сдвига соседних якорей. Вне известных времён используется скорость 75 км/ч и те же условные стоянки. Противоречивые времена не должны приводить к `NaN` или сдвигу якорей.

Внутренняя конечная: стоянка 120 секунд от прибытия, затем поезд исчезает. Для внешней конечной поезд покидает границу геометрии и постепенно растворяется за 30 секунд. Для рейса через Рижский вокзал растворение начинается после отправления от Дмитровской. Весь поезд исчезает, когда вышел за покрытие; GPS-точности нет.

## Карта и тайлы

Слои снизу вверх: подложка → отдельное затемнение → линии → станции → поезда. Затемнение составляет 16% днём и 68% ночью, не фильтрует PNG и не влияет на геометрию.

Тайлы запрашиваются только внутри коридора 500 м вокруг пути и станций. Пересечение проверяется до чтения кэша и сети; внешняя серая ячейка не получает `src` или `fetch`. Массовой предзагрузки нет. Частично пересекающий коридор PNG показывается целиком.

`src/tile-cache.js` кэширует реальные просмотры: CacheStorage — до 2000 тайлов на 30 дней; память — 128. Одинаковые запросы объединяются, Web Locks предотвращают повторные запросы из соседних вкладок одного origin. Ключ кэша включает стиль/z/x/y, без API-ключа. Постоянное хранилище требует localhost или HTTPS и разрешения браузера.

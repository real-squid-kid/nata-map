# Архитектура nata-map

Актуализировано 2026-10-07: пользователь подтвердил PHP для сервера/сборщика и Node.js для фронта. Исходная архитектура 0.3 сохранена в архиве; стек без сборщика фронта из неё заменён на Vite + Tailwind. Предметные решения сохранены.

## Покрытие и данные

Весь D2 Нахабино — Подольск: 37 станций, 23 ID API. Станции без ID имеют `pollEnabled=false`: они остаются на карте без вымышленного расписания. Показываются все пригодные электрички API, включая пригородные и экспрессы. Покровское — ID 3979 по справочнику источника; Пл. трёх вокзалов (3986) помечена там как отключённая и отвечает HTTP 503.

`config/stations.json` содержит исходные `location`, проекции `trackLocation`, `trackOffsetMeters`, `alongTrackMeters` и зоны направления. `config/railway.geojson` содержит непрерывную линию OSM из 1340 вершин, длина 81536,651 м; продолжения от проекций Нахабино/Подольска около 794/783 м. `cumulativeMeters` соответствует вершинам. Источник — пользовательский экспорт 119 путевых сегментов и реальные продолжения OSM API; Overpass не участвует в работе приложения.

GeoJSON использует [долгота, широта], Leaflet — [широта, долгота]. Метры — геодезические, средний радиус Земли 6371008,8 м. Для привязки станций использована локальная проекция. Расстояния сохранены в данных; не заменять их расстояниями между прямыми отрезками станций.

Направление вдоль геометрии `travelDirection` устойчиво: +1 к Подольску, −1 к Нахабино. Севернее Курской API `toMoscow=true` означает +1, южнее −1; зона станции задаёт преобразование. Карточка показывает «В Москву» до остановки на Курской, после неё «Из Москвы», без разворота состава. Одна репрезентативная траектория используется для обоих направлений; конкретные станционные пути не моделируются.

## Процессы и компоненты

- Vite — локальная разработка и сборка фронта; обычные JS ES-модули, Tailwind CSS, Leaflet 1.9.4.
- PHP HTTP-сервер — готовая сборка/публичные конфиги и общий снимок; в разработке Vite проксирует `/api` на PHP.
- Отдельный PHP CLI-сборщик — upstream API, нормализация, история, атомарная публикация снимка. Долгий цикл никогда не запускается HTTP-запросом.
- JSON в `var/` — состояние и история, без обязательной базы данных. Весь каталог не публикуется: HTTP отдаёт только разрешённую клиентскую проекцию.
- Чистые JS-модули рейсов/движения — сопоставление наблюдений и положение по абсолютному времени.
- Слой карты — геометрия, фильтрация тайлов, станции, поезда, карточки, анимация.

PHP отдаёт `/api/health` и `/api/state`. Сборщик, нормализация, история, сопоставление рейсов и анимация реализованы для MVP-1. Размещение локальное; позднее TimeWeb. Деплой и Sites сейчас не нужны.

Слой карты реализован в `src/map.js`; геометрический фильтр — в `src/corridor.js`, запросы PNG — в `src/corridor-tiles.js`, геометрия — `src/geometry.js`, экранная раскладка состава — `src/train-layout.js`, SVG-спрайты и капсулы — `src/train-renderer.js`, рейсы — `src/trips.js`, движение — `src/motion.js`, локальный polling — `src/api.js`. Leaflet сначала получает начальный вид через `fitBounds`, затем добавляются слои и настраиваются DOM-элементы маркеров. Статичная карта и живая подложка приняты пользователем; новые режимы и карточки проверяются Playwright в headless Edge.

Порядок слоёв снизу вверх: tilePane (200), dimming (250), routes (350), stations (450), trains (550), подсказки/карточки и органы управления выше. Затемнение 16% днём и 68% ночью — отдельная неперехватывающая клики панель, геометрия сохраняет яркость; PNG не изменяются. Цвета D1–D4 из `config/app.json` применяются к линиям, станциям и поездам. Голова белая, хвост красный, свечение зависит от режима; положение огней зависит от направления движения.

## Опрос и состояние

1. Один сборщик с блокировкой параллельного запуска читает сохранённое состояние.
2. Последовательно запрашивает 23 ID из `pollStationApiIds` без фильтра направления.
3. Между началами любых upstream-запросов минимум 1000 мс, включая повторы и другие endpoint'ы.
4. После завершения последней попытки полного цикла пауза 300 с. При перезапуске с увеличенной паузой следующий цикл не начинается раньше последнего завершения + новая пауза.
5. Ошибки не стирают последние успешные данные; обновившиеся станции могут сосуществовать с прежними снимками остальных.
6. Публикация снимка атомарная. Клиент может читать его каждые 5 с; вкладки не увеличивают upstream-частоту.

Снимок станции: `fetchedAt`, `lastSuccessfulAt`, нужные поля поездов, статус обновления и ошибка последней попытки. История сохраняет полученные времена. Исчезновение записи из ближайших отправлений не означает отмену и не удаляет её прошлую временную точку. Сырые внутренние адреса оборудования не сохраняются.

Сопоставление по устойчивому `trainNo` и дате/временному окну рейса. Дата по Москве назначается рейсу целиком по первой известной точке. После полуночи согласованные наблюдения присоединяются к тому же рейсу; номер следующего дня получает новый ключ. Новое наблюдение той же станции заменяет прошлый якорь этого рейса; тексты карточки сохраняют станционный контекст.

Окно объединения — 3 часа, история — 36 часов, параметры в `config/app.json`. Ключ сопоставления: номер и устойчивое `travelDirection`, вместо постоянного `toMoscow`. Плановое время используется для идентичности при наличии, иначе время отправления. Повтор того же номера на той же станции дальше 30 минут по плановому времени исключает объединение. backend назначает стабильный `runId`, наблюдение станции заменяет её якорь. Полночь, смена API-направления через Курскую, повтор номера и уточнение задержки покрыты проверками. Это эвристика; уникального ID рейса источник не предоставляет.

Снимок `var/state.json` атомарно содержит станции, наблюдения и статус сборщика; это авторитетное состояние после перезапуска. `var/observations.json` — дополнительная копия истории. Сборщик блокирует `var/collector.lock` через flock. Начало последнего запроса и время следующего цикла сохраняются до обращения к источнику/после цикла, чтобы быстрый перезапуск не обходил лимиты. HTTP-запросы не запускают сборщик. Источник отвечает через PHP cURL, либо системный curl.exe/curl без shell; проверка TLS не отключается. В данной Windows-установке PHP нет curl/openssl, используется curl.exe с Schannel.

## Движение

Источник якоря: `departureTime`. `scheduleTime` и `delaySeconds` доступны карточке; семантика задержек пока не проверена, задержку дополнительно не прибавлять.

Для якоря d прибытие = d − 15 с, отправление = d + 15 с. Поезд с d=12:34:30 стоит с 12:34:15 до 12:34:45. Секунды API сохраняются без округления.

Между известными станциями A и B: a = dA + 15 с, b = dB − 15 с. Для промежуточных станций без API резервируется по 30 с условной стоянки, остаток времени распределяется по расстоянию. Известные времена сохраняются. Если стоянок нет, позиция `sA + (now-a)/(b-a) × (sB-sA)`. Если интервал не вмещает условные стоянки, применяется интерполяция без них; при b <= a — резервный режим и диагностика противоречивых времён. Текст `stops` не разбирается.

Для одного якоря либо вне известного интервала: 75 км/ч, до первой известной станции обратный расчёт от прибытия, после последней прямой от отправления. Резервный режим включает 30-секундные условные стоянки на станциях конфига, без неизвестных остановок. Обратный расчёт учитывает стоянки, чтобы не сдвинуть заданный якорь.

Если конечная сопоставлена со станцией в геометрии: стоянка 120 с с прибытия, затем исчезновение; обычные 30 с не добавляются. Удалённая/неизвестная конечная остаётся текстом. Поезд исчезает, когда весь состав покидает покрытие; край не становится настоящей конечной.

Длина состава 160 м: центр s, концы s±80 м, линия повторяет все изгибы пути. Ширина и зона клика задаются в пикселях. Состав на границе рисуется только внутри геометрии до полного выхода.

Днём ниже z14 состав — капсула с обводкой и тенью; с z14 шесть отдельных SVG-вагонов: белый, четыре цвета диаметра, красный. Ночью капсулы целиком светятся тёплым белым до z14 включительно, вагоны появляются с z15; голова светится белым, хвост красным. Каждый вагон ориентирован по своему отрезку линии, между ними зазоры. Встречные направления смещаются на ±8 px по нормали; расчёт движения, метры и времена от этого не меняются. Ширина вагона 10 px, раздельные зоны клика. SVG занимает viewport карты и обновляет viewBox при pan/zoom/resize.

`requestAnimationFrame` каждый кадр вычисляет положение из текущего абсолютного времени, не накапливает шаги. Устаревание API не замораживает движение: используются последние успешные времена, выводится время обновления. Жизненный цикл поезда сохраняется; новые неизвестные рейсы при сбое не появляются. После обновления корректировка положения допустима.

## Тайлы

Thunderforest Transport PNG, прямые браузерные запросы. Ключ из локальной `.env` доступен браузеру. Без ключа геометрия отлаживается на сером фоне.

Коридор: 500 м вокруг линии и 37 станций. Собственный `GridLayer/createTile` проверяет пересечение всего прямоугольника тайла с коридором ДО кэша и внешнего `fetch`. Полностью внешний тайл — серая ячейка без запроса. Проверки одного центра недостаточно. Географические метры учитывают широту; сырые метры Web Mercator непригодны.

Реализация использует локальную проекцию с масштабом долготы по средней широте и сферическим радиусом 6371008,8 м. Это приближение для данного D2, не универсальный фильтр всего МЦД. Расстояние считается от прямоугольника до каждого отрезка линии и исходных точек станций; углы буфера круглые. Zoom 9–18, обзор ≤14, отступ области 20% в `config/app.json`. `keepBuffer=0`, запросы при установившемся виде, без предзагрузки.

Частично пересекающийся PNG загружается целиком; строгой визуальной маски нет. Bounds и zoom ограничивают участок, но не заменяют фильтр. Zoom выбрать при просмотре карты. Анимация не перезагружает тайлы.

`src/tile-cache.js`: постоянный CacheStorage (`nata-map-tiles-v1`) для реально просмотренных тайлов, максимум 2000 записей, срок 30 дней; LRU-память на 128 изображений. Ключ включает стиль/z/x/y, без API-ключа. Перед сетевым GET сначала память и диск; одинаковые запросы внутри вкладки объединяются, Web Locks предотвращает дубли между вкладками одного origin. HTTP-ошибки и ответы не с типом image/* не сохраняются. Счётчики разделяют сетевые загрузки, кэш и ожидающие ячейки. CacheStorage работает на localhost/HTTPS; при недоступном диске остаётся кэш текущей вкладки. При выгрузке тайла blob URL освобождается. Кэширующего прокси и массовой предзагрузки нет. Атрибуции Thunderforest/OpenStreetMap сохраняются.

## Карточки и диагностика

- Станция: название при наведении, карточка трёх следующих поездов в каждом направлении «в Москву» / «из Москвы» и время обновления при клике. Лимит только интерфейсный, полный снимок/история сохраняются.
- Станция без ID: «Источник расписания для этой станции не подключён». Неуспешный опрос станции с ID показывается как недоступность/последние успешные данные.
- Поезд: номер и конечная при наведении; тип, конечная, исходный `stops`, известные времена и режим расчёта при клике. При пересечении составов допустим выбор рейса из списка.
- Записи без номера, пригодного времени, направления или привязки станции остаются в списке с причинами. Один якорь достаточен для fallback. Отсутствующие тип/конечная сами по себе не запрещают движение.

## Этапы и проверка

1. Статичная карта: линия и пять станций, hover/click, серый фон, коридорный слой. Проверка в браузере: клики, pan/zoom, Network без внешних тайлов.
2. Сборщик: живой контракт трёх станций, лимит запросов, блокировка, атомарные снимки, сохранение истории, ошибки и `needReload`.
3. Рейсы и позиции: фиксированные примеры двух якорей/одного якоря, стоянки ±15 с, fallback со стоянками, противоречивые времена, отсутствие номера, повтор номера и полночь.
4. Анимация: 160 м, изгибы, конечная 120 с, полный выход за край, старая выдача, восстановление вкладки и корректировка по новому снимку.

Статичная схема из прошлого обсуждения не является приложением. Точность GPS не проверяется: GPS-данных нет.

## Расширение по ответу пользователя

Полный D2 Нахабино — Подольск активен. Каталог — `config/d2-stations.json`; рабочие проекции — `config/stations.json`. Геометрия берётся из отношения OSM и реальных продолжений у конечных; воспроизведение импорта — в docs/D2_GEOMETRY.md.

До остановки на Курской поезд идёт на Москву, после — от Москвы. Направление по зоне станции нормализуется в сборщике; старые наблюдения мигрируют при запуске. Движение и подпись карточки используют устойчивое направление и текущую позицию. Окно объединения расширено до 3 часов.

Нахабино/Подольск либо другая распознанная конечная внутри D2: 120 с от прибытия и исчезновение. Внешняя конечная: нормальная стоянка 30 с у края, движение дальше, opacity 1→0 за edgeFadeSeconds (сейчас 30). Для полного растворения требуется продолжение геометрии минимум на пройденное за fade время расстояние с запасом на длину состава; не рисовать вымышленные прямые продолжения.

Рижский вокзал: после отправления от Дмитровской opacity 1→0 за 30 с. При известном якоре начало — departureTime+15 с; при отсутствии — fallback с промежуточными стоянками. Правило направления +1 и алиасы — в конфиге. Разворот физических путей ветки не моделируется.

Станционный фокус z15, независимые details для списка и расписания. Список имеет собственную прокрутку 240–320px. Кнопка разворачивания заполняет viewport браузера; Esc возвращает панель. Карточки временно переносятся в overlay справа, сохраняя обработчики и обновление данных, после выхода возвращаются в sidebar. ResizeObserver обновляет Leaflet, навигационные bounds учитывают половину viewport для центрирования крайних станций.

`src/theme.js` выбирает ночь с19:00 до07:00 Europe/Moscow. Ручной override привязан к периоду день/ночь, сохраняется через reload и полночь и перестаёт действовать на следующем переходе. Подложка сглаживается только у запрещённых соседей:32px CSS-полосы с blur5px/градиентом внутри разрешённого тайла; проверка соседей геометрическая, без fetch.

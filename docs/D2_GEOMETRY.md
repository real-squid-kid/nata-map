# Геометрия D2: источник и импорт

Импорт выполнен 2026-10-07 из `var/d2_RAW.geojson`: 119 сегментов соединены в одну линию, все 37 станций расположены в правильном порядке, максимальное отклонение координат от пути 20,131 м. У конечных добавлено по 800 м реальной железной дороги через OSM API: продолжения от проекций станций около 794/783 м. Рабочая линия — 1340 вершин, 81536,651 м; исходный экспорт и кэш ответов остаются в игнорируемом `var/`.

Повторить импорт из сохранённых исходных данных:

```powershell
node scripts/import-d2.mjs var/d2_RAW.geojson
npm run check
```

`scripts/extend-d2.mjs` получает небольшие соединённые продолжения через OSM API, кэширует ответы и выдерживает интервал ≥1 с. Ему нужен локальный полный исходный ответ отношения `var/d2-route-full-preview.json`, использованный при подготовке. Повторные сборки приложения не обращаются к OSM. Продолжения хранятся в `var/d2-extensions.geojson`, их OSM way ID сохранены в рабочем GeoJSON. Геометрия проходит проверки связности, ориентации, накопленных метров, проекций станций и достаточного запаса для ухода поезда.

## Получение исходного экспорта

Вставить запрос из `scripts/d2-geometry.overpassql` в [Overpass Turbo](https://overpass-turbo.eu/):

```overpass
[out:json][timeout:60][maxsize:16777216];
relation(10309306)->.d2;
way(r.d2:"")["railway"="rail"];
out skel geom;
```

Это путевые участники одного [отношения Нахабино → Подольск](https://www.openstreetmap.org/relation/10309306), без платформ, зданий, станционных объектов, второго направления и рекурсивной выгрузки узлов. Один путь достаточен: поезда обоих направлений рисуются на условных соседних путях.

Состав отношения проверен 2026-10-07 через первичный [OSM API](https://api.openstreetmap.org/api/0.6/relation/10309306.json): 119 путевых сегментов, 1430 координат с учётом повторяющихся концов сегментов. Эквивалентный компактный GeoJSON, построенный из OSM API, занимает 46 573 байта. Экспорт Turbo с отступами будет больше; это оценка по проверенным данным, не ограничение размера ответа. `maxsize` ограничивает серверную память, а не размер экспорта.

Синтаксис пустой роли и `out skel geom` соответствует [документации Overpass QL](https://wiki.openstreetmap.org/wiki/Overpass_QL). Прямое выполнение из среды разработки получило HTTP 406/500 на публичных Overpass; геометрия и состав проверены через OSM API. Это не подтверждение успешного выполнения в Turbo.

## Что сохранить

1. Вставить запрос целиком и нажать «Выполнить» / Run. Он не зависит от текущего вида карты.
2. Выбрать «Экспорт» → «GeoJSON» → скачать файл. Не применять автоматический ремонт запроса с добавлением рекурсии `>;`.
3. Положить файл, например, в `var/import/d2-railway.geojson` и сообщить его путь. `var/` уже исключён из Git; каталог при необходимости создать.

Не ограничивать вывод произвольным `out 100`: это отрежет часть линии. Станции уже сохранены отдельно в `config/d2-stations.json`, повторно выгружать их не нужно.

Импорт соединяет сегменты по совпадающим концам, проверяет единственность цепочки и привязки станций, формирует накопленные метры и активные конфиги. Продолжения за Нахабино/Подольск нужны для движения внешних рейсов с растворением; они следуют реальным связанным рельсам, а не вымышленным прямым отрезкам. Как и основной маршрут OSM, путь репрезентативный: точные платформенные пути конкретных рейсов не моделируются.
